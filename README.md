# 模型路由观察器

面向 **SillyTavern 1.18.0** 的独立前端扩展。它不写入预设、角色卡或聊天消息，而是观察酒馆向聊天补全后端发出的请求，以及返回给酒馆的响应副本。

## 它记录什么

- 请求正文中填写的模型名；
- 产生正文/推理文本的流式分片分别报告了什么模型，以及各自出现次数；
- 所有 SSE 分片报告的模型及次数；
- 最终携带 `usage` 的分片报告的模型；
- 回复 ID、少量安全白名单响应头、系统指纹和计费来源（如果接口有提供）；
- 上述几层元数据是否互相冲突。
- 每条记录可复制酒馆实际发送的完整请求正文；
- 每条记录可复制酒馆实际收到的完整原始 SSE 或 JSON 响应。

完整请求与原始回复可能包含提示词、聊天内容和模型输出，因此扩展只把它们临时保存在**当前页面的内存**中，刷新或关闭页面后自动消失，也不会包含在“导出 JSON”中。模型名称、分片计数、回复 ID 等元数据会保存在当前浏览器的 `localStorage`，最多 50 条，可随时清空或导出。

扩展不会读取或保存 API Key、Cookie、Authorization 请求头或完整请求头。

## 手动安装

1. 关闭 SillyTavern，或准备在复制完成后重启。
2. 将整个 `SillyTavern-Model-Trace` 文件夹复制到：

   `SillyTavern/public/scripts/extensions/third-party/`

3. 最终路径应为：

   `SillyTavern/public/scripts/extensions/third-party/SillyTavern-Model-Trace/manifest.json`

4. 启动或刷新 SillyTavern。在扩展管理页确认“模型路由观察器”已启用。
5. 页面右下角会出现“模型”按钮；发送消息后点击它查看记录。
6. 在对应记录底部点击“复制完整原始输入”或“复制完整原始回复”。生成期间已经收到数据时，也可用“复制当前原始回复”；用户终止后可用“复制已接收原始回复”。

如果按钮没有出现，请按 `Ctrl+F5` 强制刷新一次，并在扩展管理页检查是否被禁用。

## 如何读结果

- **请求模型**：酒馆发给其后端的 `model` 字段。它只代表请求意图。
- **正文分片报告**：实际携带生成文本的流分片自报的模型。这通常是前端能取得的最有价值证据。
- **全部分片报告**：包括空增量、结束标记、usage 等所有分片。
- **最终 usage 模型**：最终统计/计费分片上的模型标记；它可能与正文分片不同。

例如：

- 请求模型为 `claude-fable-5`；
- 正文分片全部为 `claude-opus-4-8`；
- 最终 usage 又写成 `claude-fable-5`；

扩展会同时标记“请求模型与正文模型不同”和“最终 usage 标记与正文模型不同”。

## 重要限制

这是**路由元数据检查器**，不是模型指纹鉴定器。模型名、回复 ID、usage 和响应头都由接口/供应商声明。如果上游供应商统一伪造这些字段，浏览器端无法仅凭一次回复证明底层究竟运行了哪个模型。要进一步确认，需要供应商日志、可信计费记录或带签名的上游回执。

“完整原始输入”是浏览器实际发往 SillyTavern 聊天补全后端的 JSON 请求正文；它与控制台中展开的 `Chat Completion request` 对象内容相同，但保持网络请求使用的 JSON 文本格式。“完整原始回复”是浏览器解码后收到的完整 SSE 文本（保留 `data:` 行和 `[DONE]`）或非流式 JSON 文本。

扩展不依赖服务器正确填写 `Content-Type`：即使响应头为空，也会根据响应正文自动识别并解析 SSE。用户主动终止时，上游尚未发送的内容不可能找回，但终止前已经到达浏览器的原始分片会保留并可复制。
