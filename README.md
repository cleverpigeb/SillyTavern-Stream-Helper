# 酒馆流式助手

面向 **SillyTavern 1.18.0 及以上版本**的独立前端扩展，用于观察聊天补全请求与流式响应、核对上游报告的模型，并快速复制调试所需的原始输入和回复。

扩展只旁路读取请求与响应副本，不会修改预设、角色卡、聊天消息或模型输出，也不依赖 Tavern Helper、服务器插件或其他第三方扩展。

## 在 SillyTavern 中安装

复制以下 GitHub 仓库链接：

```text
https://github.com/cleverpigeb/SillyTavern-Stream-Helper
```

然后在 SillyTavern 中完成安装：

1. 打开顶部的“扩展”面板。
2. 选择“安装扩展”。
3. 将上面的仓库链接粘贴到输入框中。
4. 分支或标签留空，以使用仓库默认的 `main` 分支。
5. 点击安装；如果出现第三方扩展安全提示，请确认来源无误后继续。
6. 安装完成后，确认扩展管理器中的“酒馆流式助手”已启用。

扩展启用后，页面右下角会出现“流式”按钮。发送一条聊天消息，再点击该按钮即可查看记录。

如果按钮没有出现，请刷新页面；仍未出现时，可按 `Ctrl+F5` 强制刷新，并检查：

- SillyTavern 版本是否不低于 `1.18.0`；
- UI 扩展功能是否已启用；
- 扩展是否在管理器中被禁用；
- 是否已经存在同名扩展目录，导致安装失败。

## 插件功能

### 核对请求模型与上游模型

插件会观察 SillyTavern 发往聊天补全后端的请求，并记录：

- 请求正文中的模型名称；
- 携带正文或推理文本的流式分片所报告的模型及出现次数；
- 所有 SSE 分片所报告的模型及出现次数；
- 最终携带 `usage` 的分片所报告的模型；
- 回复 ID、系统指纹、计费来源和少量安全白名单响应头；
- 请求模型、正文模型和 usage 模型之间是否存在冲突。

当检测到以下情况时，记录会显示警告：

- 响应没有报告模型；
- 正文分片中混有多个模型；
- 请求模型与正文分片报告的主要模型不同；
- 最终 usage 模型与正文模型不同。

例如，请求模型是 `claude-fable-5`，正文分片报告 `claude-opus-4-8`，最终 usage 又报告 `claude-fable-5`，插件会同时标记请求模型和 usage 模型与正文模型不一致。

### 复制完整原始输入

每条记录都提供“复制完整原始输入”按钮。复制内容是浏览器实际发往 SillyTavern 聊天补全后端的 JSON 请求正文，其中可能包含：

- 系统提示词；
- 聊天上下文；
- 角色与用户消息；
- 模型名称及生成参数；
- 工具或后端相关配置。

插件不会复制 API Key、Cookie、Authorization 请求头或完整请求头。

### 复制完整原始回复

插件会保留浏览器解码后实际收到的原始响应：

- 流式响应保留完整 SSE 文本，包括 `data:` 行和 `[DONE]`；
- 非流式响应保留原始 JSON 文本；
- 生成过程中可以复制当前已经收到的部分；
- 用户终止生成后，可以复制终止前已经到达浏览器的内容。

上游尚未发送的数据无法在用户终止后恢复。

### 自动清理记录

插件默认只保留最近 **6 条**记录。用户可以在面板中修改保留数量，可设置范围为 **1–1000 条**。

记录超过设定数量后，插件会自动删除最老的记录，同时清理与该记录对应的内存原文。降低保留数量时，超出新上限的旧记录也会立即被清理。刷新或关闭页面会清除当前全部记录。

### 导出与清空

- “导出 JSON”会导出当前保留的模型、分片计数、回复 ID、状态等元数据；
- “清空记录”会删除全部本地记录和当前页面内存中的原文；
- 导出的 JSON 不包含完整提示词或完整原始回复。

## 数据保存与隐私

请求记录、完整请求和原始回复都只保存在**当前页面的内存**中：

- 刷新或关闭页面后自动消失；
- 请求模型、分片计数和回复 ID 等元数据同样不会写入 `localStorage`；
- 不包含在导出的 JSON 中；
- 记录被自动清理时，对应原文也会从内存中移除。

只有用户设置的记录保留数量会写入当前浏览器的 `localStorage`，以便刷新页面后继续使用相同设置。

## 如何理解“实际模型”

插件显示的“实际模型”来自上游响应分片自行声明的模型字段。它是浏览器端能够获得的重要路由证据，但不是模型指纹鉴定结果。

如果供应商统一改写或伪造模型名、回复 ID、usage、系统指纹和响应头，插件无法仅凭一次浏览器响应证明底层实际运行了哪个模型。进一步确认仍需要供应商日志、可信计费记录或带签名的上游回执。

## 响应兼容性

插件不依赖服务器正确填写 `Content-Type`。即使响应头为空，也会根据响应正文尝试识别 SSE 或 JSON，并记录无法解析的事件数量。
